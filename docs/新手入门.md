# acskill 新手入门

你可能是看到这个仓库里的 Skill，想知道：**我应该装哪个、怎么开始、第一句话该怎么说、最后能得到什么。**

这份说明书就是给第一次使用的人看的。你不需要先读完 `SKILL.md`，也不需要手动执行一堆脚本。先选对 Skill，把真实任务交给 Agent 即可。

当前仓库主要包含两个 Skill：

| Skill | 当前版本 | 适合解决什么问题 | 主要产出 |
| --- | --- | --- | --- |
| `acs-gongkao-geo-research` | v2.2 | 调研某个地区的公考机构 / 老师 IP 在 AI Answer、公开网页与 GEO 资产层面的竞争情况 | 一份正式 Word / DOCX GEO 研究报告 |
| `acs-second-brain-manager` | v1.0 | 接管和长期管理本地 Markdown / Obsidian 知识库 | 查询、入库方案、知识更新、来源追踪、健康检查 |

如果你只是想先试一个，直接跳到下面对应的 Skill 即可。

---

## 1. 安装

`acskill` 是一个公开的 Agent Skills 仓库。推荐使用支持 Skills 的 Agent 环境安装。

### 安装公考 GEO 调研 Skill

```bash
npx skills add https://github.com/iamaresfive-code/acskill --skill acs-gongkao-geo-research
```

### 安装第二大脑知识库管理器

```bash
npx skills add https://github.com/iamaresfive-code/acskill --skill acs-second-brain-manager
```

如果你的 Agent 已经支持直接从 GitHub 仓库安装 Skills，也可以直接把仓库地址交给 Agent：

```text
https://github.com/iamaresfive-code/acskill
```

然后告诉它要安装哪个 Skill。

安装完成后，如果当前 Agent 没有立刻识别新 Skill，重新开启一个会话再使用。

> 不同 Agent 的本地文件、联网、浏览器、Python、Word 生成能力不同。Skill 负责工作方法和流程，实际能否联网、读取本地文件或生成 DOCX，取决于你使用的宿主 Agent 是否提供对应工具。

---

## 2. 第一次怎么用

你不需要记复杂命令。

最稳妥的方式是：**直接点名 Skill + 说清真实任务。**

例如：

```text
使用 acs-gongkao-geo-research 调研天津公考 GEO。
必须覆盖津仕、北宋，允许系统补充其他竞争主体。
```

或者：

```text
使用 acs-second-brain-manager 接管我的 Obsidian 知识库。
知识库路径是 /Users/xxx/Documents/MyVault。
第一次先只读扫描，不要修改任何文件。
```

Skill 会继续处理流程，而不是要求你先学会它内部所有脚本。

# 一、公考机构 GEO 调研

## 3. 这个 Skill 是干什么的

`acs-gongkao-geo-research` 用来研究：

> 在某个地区的公考市场里，哪些机构和老师 / IP 是真实竞争主体；AI 在无品牌问题下会不会主动提到它们；这些差异可能和哪些公开 GEO 资产有关。

它不是简单搜几个关键词，也不是把搜索结果数量直接当成“GEO 排名”。

核心分三层：

```text
先确认研究谁
↓
再测 AI 到底提不提
↓
最后用公开资产解释为什么
```

最终正式交付固定为：

```text
deliverables/report.docx
```

也就是一份 Word 咨询报告。

---

## 4. 第一次跑 GEO，你只需要给三件事

### ① 地区

例如：

```text
广东
天津
山东
江苏
```

### ② 你希望一定覆盖的机构、品牌或老师 IP

这叫 Seed List。

例如：

```text
天津：津仕、北宋
广东：粉笔、超格、上岸村、粤政喵
```

Seed 的作用是：**保证这些主体不会漏掉。**

它不代表这些主体会自动获得更高分，也不代表它们一定进入最终第一梯队。

### ③ 是否允许系统补充竞争主体

推荐回答：

```text
允许系统补充。
```

这样 Skill 会在你提供的名单之外继续发现本地机构、全国基准机构、老师 / IP 和观察主体。

---

## 5. 一个最推荐的新手输入

```text
使用 acs-gongkao-geo-research 调研天津公考 GEO。

地区：天津。
必须覆盖：津仕、北宋。
允许系统补充其他竞争主体。

先完成市场主体发现并给我确认，再开始正式 Measurement。
最终按 Skill 默认规范输出 Word 报告。
```

你不需要再告诉它“做 Excel 还是 Word”，当前正式输出就是 DOCX。

---

## 6. 它为什么不会一上来就给排名

因为如果一开始连“这个地区到底有哪些真实玩家”都没确认，后面的排名再精确也可能是在错名单里排序。

所以它会先建立 Market Universe，大致区分：

- 全国基准机构；
- 本地 / 区域机构；
- Expert / 老师 IP；
- 观察主体。

然后先让你确认研究范围。

**确认 Market Universe 之后，才进入正式 AI Answer Measurement。**

这是这个 Skill 和“直接搜十家机构然后打分”的最大区别之一。

---

## 7. AI Measurement 测的是什么

核心问题不是：

> “网上谁的文章最多？”

而是：

> “当用户问一个没有提前写品牌名的问题时，AI 会主动推荐谁？”

因此会区分：

- Raw Mention：有没有被提到；
- Nomination：是不是正向推荐 / 列入选择；
- Top3：是否进入前 3；
- First Mention：是否第一提及；
- Citation：是否存在实体级引用支持；
- Engine Coverage / Cross-model Consistency：跨引擎或模型表现是否稳定；
- Robustness：不同重复采样 / 变体下结果是否稳定。

机构和老师 IP 使用不同 Measurement Target。

如果一个实体经过人工证据审核后确实同时属于两种入口，可以是：

```text
measurement_target = both
```

这时会分别计算 institution 和 ip 两套指标，不把两种分母混在一起。

---

## 8. GEO 报告不能怎么理解

这份报告研究的是 **AI Answer Visibility + GEO Asset Readiness**。

它不能直接等同于：

- 真实市场份额；
- 真实招生规模；
- 广东 / 天津 / 山东所有机构的绝对实力排名；
- “所有 AI 的统一结论”；
- 搜不到 = 机构不存在；
- 某次没被推荐 = GEO 为零。

AI 结果必须放在记录下来的 query、engine、context、observation date 和 robustness 条件下解释。

---

## 9. 公开资产层看什么

AI Measurement 之后，Skill 会再看公开 Web 资产，解释为什么某些主体更容易被 AI 理解、引用和关联。

常见维度包括：

- 实体清晰度；
- 地域语义密度；
- 开放 Web 资产；
- 外部权威性；
- 内容深度与新鲜度；
- 数据 / 工具型资产；
- 平台覆盖。

这里有一个重要规则：

> **本次没有找到证据，不等于这个主体一定没有。**

完全缺证据时可以保留 unknown / 空值，而不是为了凑完整排名硬填 0 分。

---

## 10. 适合怎么问

### 调研一个地区

```text
帮我做广东公考 GEO 深度研究，重点覆盖粉笔、超格、上岸村、粤政喵，允许补充其他竞争机构和老师 IP。
```

### 指定几家重点对比

```text
做天津公考 GEO，重点比较津仕和北宋，但不要只研究这两家，仍然先建立完整 Market Universe。
```

### 指定一个机构作为重点对象

```text
研究超格教育在山东公考 GEO 里的位置。
超格必须进入 Seed List，同时补充山东真实竞争主体，再做正式对比。
```

### 想看老师 IP

```text
做广东公考 GEO，除了机构外，把本地有明显影响力的老师 / IP 也纳入研究，并单独使用 ip Measurement Target。
```

# 二、第二大脑知识库管理器

## 11. 这个 Skill 是干什么的

`acs-second-brain-manager` 是一个本地 Markdown / Obsidian 知识库管理 Skill。

你可以把它理解成：

> 一个长期帮你管理电脑知识库的 AI 管家。

它不是简单把所有聊天和文件都塞进一个文件夹。

它更关心：

- 旧资料放在哪里；
- 新资料应该更新还是新建；
- 同一个人物 / 机构是不是重复了；
- 哪个结论才是当前版本；
- 事实来自哪里；
- 什么是用户判断，什么是 Agent 推断；
- 项目状态有没有矛盾；
- 知识库有没有碎片化、断链或重复。

---

## 12. 第一次接管已有知识库

第一次不要让 AI 直接“帮你整理全部文件”。

推荐直接这样说：

```text
使用 acs-second-brain-manager 接管这个知识库：
/Users/xxx/Documents/MyVault

这是一个已有知识库。
第一次只做只读扫描，不要创建、移动、重命名、修改或删除任何文件。
先给我 Knowledge Base Understanding Report。
```

Skill 会先理解你已经存在的：

- 目录；
- README / AGENTS / 规则文件；
- frontmatter；
- Wiki Link / Markdown Link；
- 原始材料目录；
- 项目结构；
- 命名习惯；
- 已有索引和治理规则。

扫描结果只是“观察”，不是它有权自动重构你的知识库。

---

## 13. 最常用的说法

不需要背命令，直接说自然语言即可：

```text
把这份资料入库，先给我方案，不要马上写。
```

```text
我以前怎么看加盟模式？只查询，不要写入。
```

```text
更新一下这个机构的信息，先检查是否已经有对应页面。
```

```text
这条信息和我以前的判断有没有冲突？
```

```text
帮我查这个老师目前和哪个机构有关。
```

```text
检查这个项目现在是什么状态，不要仅凭日期判断已经结束。
```

```text
做一次知识库健康检查，只报告问题，不自动修复。
```

---

## 14. 新资料为什么不会直接写进去

这个 Skill 把长期知识库当成“可持续维护的当前知识”，不是聊天流水。

新资料进入之前，会先判断属于哪种动作：

| 动作 | 含义 |
| --- | --- |
| `UPDATE` | 新事实应该更新已有知识 |
| `MERGE` | 新资料应该合并进已有页面 |
| `CREATE` | 确实形成新的实体、概念、项目、案例或流程 |
| `PENDING` | 关键事实冲突，暂时不能确认 |
| `SOURCE_ONLY` | 原始资料值得保存，但暂时不需要提炼成知识页 |

默认推荐 `confirm-first`：

> 先分析、查重、给完整写入方案；你确认后，再在批准范围内执行。

---

## 15. 原始材料和知识页为什么分开

例如你有一份：

```text
某机构2026年内部交流纪要.docx
```

更推荐的结构是：

```text
原始材料
└── 某机构2026年内部交流纪要.docx

知识页
├── 机构-某机构.md
├── 公考机构渠道模式.md
└── 班型运营模式对比.md
```

原始材料回答：

> 当时到底说了什么？

知识页回答：

> 基于目前所有资料，我们现在对这件事怎么看？

以后判断变化时，知识页可以更新，但原件仍然保留并可追溯。

---

## 16. 它默认不会做什么

没有额外授权时，它默认不会：

- 第一次接管已有库就重构目录；
- 因为名字相同就自动合并人物或机构；
- 因为文件看起来旧就自动删除；
- 因为日期很久就自动把项目标为结束；
- 修改已有 PDF / Word 原件；
- 把 Agent 自己的推断包装成来源事实；
- 因为你问了一次问题就自动写知识库；
- 顺手执行大规模移动、重命名或治理结构变化。

## 17. 两个 Skill 怎么选

| 你的任务 | 用哪个 Skill |
| --- | --- |
| “帮我调查广东有哪些公考机构，以及谁在 AI 里更容易被推荐” | `acs-gongkao-geo-research` |
| “帮我研究某机构在本地 GEO 竞争里的位置” | `acs-gongkao-geo-research` |
| “帮我把 GEO 调研结果长期沉淀到知识库” | 先用 GEO Skill 做研究，再用 `acs-second-brain-manager` 管理结果 |
| “我有一堆 Word、PDF、会议记录，不知道怎么长期管理” | `acs-second-brain-manager` |
| “我以前对某件事是什么判断？” | `acs-second-brain-manager` |
| “知识库里重复内容很多，帮我体检” | `acs-second-brain-manager` |

两个 Skill 可以前后配合，但不要混成一套任务逻辑：

```text
GEO Skill 负责研究
↓
得到正式报告和证据
↓
Second Brain Skill 负责长期治理和复用
```

## 18. 怎样更新

使用 Skills CLI 安装后，可以通过：

```bash
npx skills update
```

拉取已经安装 Skill 的新版本。

如果只想更新单个 Skill，也可以使用：

```bash
npx skills update acs-gongkao-geo-research
```

或：

```bash
npx skills update acs-second-brain-manager
```

正式版本和更新记录以 GitHub 仓库的 `main`、Tag 和 Release 为准。

仓库地址：

```text
https://github.com/iamaresfive-code/acskill
```

## 19. 新手最容易犯的几个错误

### 错误 1：安装完就开始手动跑 scripts

普通使用者不需要先研究脚本。

先让 Agent 使用 Skill 完成任务；`scripts/` 更适合调试、验证和开发者使用。

### 错误 2：GEO 直接要求“给我一个绝对排名”

先确认 Market Universe，再做 AI Measurement，结论才有解释边界。

### 错误 3：把 Web 搜索量当成 AI 推荐能力

网页资产和 AI Answer Measurement 是不同层，不能混成一个数字。

### 错误 4：第二大脑一上来就要求“自动整理全部知识库”

第一次接管已有库，推荐先只读扫描和确认规则。

### 错误 5：把 Agent 推断长期写成事实

长期知识库必须区分来源事实、用户判断、Agent 推断、用户决策和待核信息。

如果你看完整篇还是不知道从哪里开始，只需要复制下面其中一句。
