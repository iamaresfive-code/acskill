# 中文客户报告契约（v2.2.1 补丁）

本文件约束唯一正式交付物 `deliverables/report.docx` 的**用户可见层**。研究底稿、审计数据、内部枚举和脚本仍保留在 Run 目录，但不得直接倾倒进客户报告。

## 1. 三层信息边界

### 客户报告层：必须给用户看

- 核心结论：谁在 AI 回答中更容易被提名，差距有多大；
- 全国品牌、本地/区域机构、老师/个人品牌分开比较；
- 换一种问法后结果是否稳定；
- GEO 资产基础、概念占位，以及哪些主体存在明显优化机会；
- 重点主体的优势、短板、优先动作；
- 区域策略与 90 天行动；
- 必要的方法边界与“不适用”说明。

### 方法附录层：可以给专业用户看

- 研究地区、AI 测量环境、回答样本数、观察日期；
- **机构推荐类问题**与**老师推荐类问题**分开计量；
- 语义等价问法的稳定性口径；
- 正式研究主体清单；
- 暂无足够公开证据、因此暂不评分的主体。

### 工程审计层：不进入客户 DOCX

- `measurement_target`、`market_role`、`query_variant_mode` 等内部字段；
- `local-core`、`native-recorded`、`semantic-retrieval-variants` 等内部枚举；
- CSV / JSON / JSONL / Python 文件名；
- Validator 错误码、脚本调用链、内部哈希与 Run 文件清单；
- Python dict / JSON 原始对象字符串；
- Annotation / Resolution / Citation 的逐行审计明细。

完整工程底稿继续保留在 Run 目录，必要时单独提供审计，不在客户报告正文展开。

## 2. 语言规则

正式报告默认使用**简体中文**。

允许保留的常用缩写仅限确有必要的 `AI`、`GEO`、`URL`、`Word / DOCX` 等。`IP` 在客户正文中优先写为“个人品牌”；不要创造“机构题”“IP题”这种只有开发者理解的缩写。

| 内部/英文术语 | 客户报告写法 |
| --- | --- |
| Market Universe | 研究主体池 |
| AI Answer Measurement | AI 回答测量 |
| institution queries | 机构推荐类问题 |
| IP / expert queries | 老师推荐类问题 |
| Nomination Rate | 提名率 |
| Top3 Rate | 前三出现率 |
| First Mention Rate | 第一位出现率 |
| Citation Rate | 引用率 |
| Query / Retrieval Robustness | 结果稳定性 / 提问稳定性 |
| GEO Asset Readiness | GEO 资产基础 |
| Concept Ownership | 概念占位 |
| AI-emergent | AI 回答中新出现的主体 |
| native | 模型直接回答 |
| programmatic | 程序创建独立会话 |
| single-engine | 单一 AI 入口 |
| unknown | 暂无可核验证据 |

正文不得出现 `Metrics`、`Entity Resolution`、`Query Matrix`、`citations`、`Seed`、`page mention` 等工程表达，应翻译成普通用户能直接理解的中文。

## 3. 图表规则

图表必须先帮助用户判断，再保证数据完整。

- 排名图使用中文标题、中文主体名、直接数值标签；
- 概念占位使用 Top N 条形图，不使用高度稀疏且难读的热力图；
- 资产排名明确写“前 N 名”，不得用“全部可评分主体”暗示完整覆盖；
- **不再把机构推荐类与老师推荐类测量混在一张散点图里。** 两类问题的样本分母不同，客户图应分别比较；
- 总览图改为“重点优化机会”：只列资产基础相对较强、但在**各自同类问题**中 AI 提名率偏低的主体；
- 机会图不允许匿名点；所有展示主体必须有名称；
- 资产分与 AI 提名率分别解读，不相加生成未经验证的综合分；
- 内部 Bucket / enum 不得直接作为图例或坐标标签；
- 正式图表必须使用可用中文字体；没有中文字体时直接 FAIL，不退化成英文或乱码。

## 4. 引用率语义

如果原 Answer 没有提供引用来源：

- 引用率在客户报告中显示为**不适用**；
- 不得显示 `0%`；
- 不得在任何说明段中写“引用率为 0”；
- 不得解释为“AI 从未引用该主体”。

只有测量环境真实提供可核验引用链时，才展示引用率。

## 5. GEO 资产证据不足

没有找到公开证据不等于 0 分。

- 有足够证据：可形成资产基础得分与等级；
- 证据不足：客户报告写“暂不评分”；
- 主表不展示内部未知字段清单；
- 可在方法附录列出“暂不评分主体”名称；
- 诊断文字里的资产得分与等级必须和最终资产评分数据一致，不允许沿用过期分析文本。

## 6. 90 天行动的对象

客户报告是竞争研究，不得误写成“替所有竞争机构建设资产”。

- 行动建议默认面向“希望提升自身 GEO 表现的机构或老师”；
- 不得出现“为全部竞争主体建立第一方页面”等不可能执行的表述；
- 复测指标是阶段性验证依据之一，不得写成唯一判据。

## 7. 自动 QA 必须阻断

客户 DOCX 出现以下情况应直接 FAIL：

- 一级标题仍是英文；
- “机构题”“IP题”等内部缩写；
- `Top3`、`Metrics`、`Entity Resolution`、`Query Matrix` 等开发者术语；
- 内部字段名或 snake_case；
- `.csv` / `.json` / `.jsonl` / `.py` 工程文件名；
- Python / JSON 原始对象字符串；
- 无引用链时把引用率写成 0；
- 工程审计清单进入客户正文；
- 关键章节只有标题没有内容。

## 8. v2.2 旧报告兼容说明

v2.2 时代已经生成的 `report.docx` 不满足 v2.2.1 客户报告语言与产品契约，升级后需要基于原持久化研究数据**重新生成报告层**。不得因此改写冻结的原始 AI 回答、标注或测量证据。
